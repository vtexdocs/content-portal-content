Los [Problemas conocidos](https://help.vtex.com/known-issues) informan a los usuarios sobre problemas identificados en la plataforma o productos VTEX, su estado actual y posibles soluciones (alternativas) o correcciones permanentes. Actualizamos constantemente estos artículos para que puedas anticipar posibles inconvenientes y saber que nuestro equipo está al tanto de ellos.

En este artículo, verás la diferencia entre Problemas conocidos, otros tipos de artículos y Mejoras de producto, así como una vista general de un artículo de Problema conocido.

## Diferencias entre Problemas conocidos y guías de resolución de problemas

Al navegar la documentación de VTEX, es importante entender las diferencias entre los tipos de artículos, los cuales tienen propósitos específicos. Por ejemplo, los artículos de Problemas conocidos alertan a los usuarios sobre problemas identificados dentro de la plataforma, proporcionando actualizaciones, soluciones alternativas o soluciones definitivas. En contraste, las guías de resolución de problemas ofrecen instrucciones paso a paso para corregir errores específicos.

A continuación, encuentra la meta, el enfoque de contenido y la audiencia entre los artículos de Problemas conocidos y otros tipos de artículos:

| **Tema** | **Problema conocido** | **Resolución de problemas** |
| --------- | --------------- | ------------------- |
| **Meta** | Informar a los usuarios sobre problemas conocidos dentro de la plataforma y productos, y sus soluciones alternativas o definitivas. | Brindar instrucciones paso a paso para resolver problemas o errores específicos. |
| **Enfoque de contenido** | Descripción del problema, impacto, solución alternativa o definitiva y actualizaciones de estado. | Pasos para resolución de problemas, mensajes de error y posibles causas. |
| **Audiencia** | Todos los usuarios que puedan verse afectados por el problema conocido. | Usuarios que experimentan problemas o errores específicos. |
| **Ejemplo de artículo** | [No se aplican beneficios ni impuestos a los servicios](https://help.vtex.com/known-issues/benefits-and-taxes-are-not-applied-to-services--4u12zyfc387daNQamFohA2) | [El Site Editor de mi tienda no funciona](https://help.vtex.com/tutorial/my-stores-site-editor-is-not-working--3A6Ois91zEZ8zpKJp1wsP2) |

## Pautas para identificar problemas conocidos o mejoras de producto

Tanto los problemas conocidos como las mejoras de producto tienen la intención de mejorar el producto. Sin embargo, mientras que los problemas conocidos se enfocan en resolver problemas existentes, las mejoras de producto buscan añadir nuevas funciones o mejorar las ya existentes.

Para ilustrar mejor la diferencia entre ellos, considere lo siguiente:

| **Tema** | **Problema conocido** | **Optimización de producto** |
| --------- | --------------- | ----------------------- |
| **Definición** | Un problema o error identificado en el producto o plataforma. | Un cambio propuesto para mejorar la funcionalidad, usabilidad o rendimiento del producto o la plataforma. |
| **Enfoque** | Solucionar problemas existentes. | Agregar nuevas funciones o mejorar las existentes. |
| **Impacto para el usuario** | Impacto negativo en la experiencia o funcionalidad para el usuario. | Impacto positivo en la experiencia o funcionalidad para el usuario. |
| **Ejemplo** | Un botón en una página no funciona como se espera. | Agregar una nueva función para filtrar los resultados de búsqueda. |

## Estructura de problema conocido

![known-issue-article-overview](https://github.com/vtexdocs/content-portal-content/blob/main/images/en/known-issue-article-overview.png?raw=true)

| **Tema del artículo** | **Descripción** |
| ----------------- | --------------- |
| 1 - Título | Título del artículo que describe el problema. |
| 2 - Nombre del producto | Tag del producto afectado por el problema. |
| 3 - Zendesk ID | Identificador único del problema conocido en Zendesk. |
| 4 - Status | Tag que describe el status del problema conocido. Estos son los status disponibles: <ol><li>`Fixed`: el problema se ha resuelto y se ha implementado una solución.</li><li>`Backlog`: el problema se ha identificado, pero actualmente no hay una fecha prevista para su solución. Puede que se le dé prioridad y se programe para un futuro release.</li><li>`Scheduled`: el problema se ha priorizado y se ha programado su solución.</li><li>`No fix`: el problema no se corregirá, probablemente debido a bajo impacto, limitaciones técnicas u otros motivos.</li></ol> |
| 5 - Publicado el | Fecha en que se creó el artículo. |
| 6 - Última actualización el | Fecha de la última actualización del artículo. |
| 7 - Resumen | Sección para describir el error. |
| 8 - Simulación | Sección para describir qué pasos son necesarios para reproducir el comportamiento. |
| 9 - Solución alternativa | Sección para describir la solución alternativa al problema, si la hay. |
